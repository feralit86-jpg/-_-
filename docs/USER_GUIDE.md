## 1. Назначение программы

**LAN Status Monitor** — консольная утилита для быстрой инвентаризации
устройств в локальной сети `/24`. Программа определяет активный сетевой
адаптер, сканирует все 254 адреса подсети и выводит таблицу с IP-адресами,
MAC-адресами, производителями, статусами доступности и временем отклика.

**Зачем это нужно:**

- быстро увидеть, кто находится в вашей локальной сети;
- отличить живые устройства от выключенных;
- определить производителя по MAC-адресу (Xiaomi, Intel, TP-Link и т.д.);
- проверить, какие порты открыты на устройствах;
- не требует установки сторонних программ и прав администратора.

1. Откройте **cmd** (Win + R → введите `cmd` → Enter).
2. Перейдите в папку проекта:
```cmd
cd путь\к\папке\lan-status-monitor
```
3. Запустите программу:
```cmd
python main.py
```

### 4.3. Что произойдёт после запуска
Программа выполнит три шага:
1. **Определит активный сетевой адаптер** (Wi-Fi или Ethernet), игнорируя VPN и виртуальные интерфейсы.
2. **Просканирует подсеть** `/24` — 254 адреса. Занимает **3–10 секунд**.
3. **Выведет таблицу** с найденными устройствами.

## 5. Использование

### 5.1. Шапка таблицы

Три строки перед таблицей показывают, **что именно** сканируется:

| Строка | Что означает |
|---|---|
| `Основной адаптер` | Имя физического сетевого интерфейса (Wi-Fi / Ethernet) |
| `Локальный IP` | Ваш IP-адрес в этой сети |
| `Сканирую` | Подсеть, по которой идёт сканирование (`192.168.70.0/24`) |

Если в `Основной адаптер` написано «Radmin VPN» или «VMware Network Adapter» — это **ошибка**: программа должна выбрать физический адаптер. См. раздел 7 («Возможные проблемы»).

### 5.2. Колонки таблицы

| Колонка | Что содержит |
|---|---|
| `#` | Порядковый номер (сортировка по возрастанию IP) |
| `Устройство` | Hostname / производитель по MAC / сырой MAC |
| `Адрес` | IP-адрес устройства |
| `Статус` | `ONLINE` / `TCP:<порт>` / `ARP` (см. 5.3) |
| `мс` | Время отклика на ping в миллисекундах |

### 5.3. Расшифровка статусов

| Статус | Что означает |
|---|---|
| `ONLINE` + число | Устройство ответило на ping. Число — время отклика в мс. |
| `ONLINE <1` | Это **ваш собственный ПК**. Ping на себя < 1 мс. |
| `TCP:445`, `TCP:80`, `TCP:22` и т.д. | Ping заблокирован (файрвол), но открыт указанный TCP-порт. **Устройство живо.** |
| `ARP` | Устройство есть в ARP-таблице (отвечает на ARP), но молчит по ping и TCP. Возможно, спит, заблокирован файрволом или за client isolation. |

**Важно:** статус `ARP` — это **не** «устройства нет». Это «устройство есть в сети, но не отвечает на наши запросы». MAC-адрес у него известен, значит, оно физически присутствует.

### 5.4. Колонка «Устройство»

Программа отображает информацию в порядке приоритета:
1. **Hostname** — если удалось получить через reverse-DNS (например, `DESKTOP-6F1OVUR`).
2. **Производитель по MAC (OUI)** — если MAC настоящий и известен (например, `Xiaomi`, `Intel`, `TP-Link`, `Apple`).
3. **`— (random MAC)`** — если MAC случайный (обычно у телефонов и ноутбуков с включённой MAC-рандомизацией).
4. **Сырой MAC** — если производитель неизвестен (например, `2c-fd-a1-58-e7-22`).

### 5.5. Итоговая строка

Внизу таблицы — сводка:

```
text
Итого: 55 пинг, 7 tcp, 6 только ARP
```

## 6. Изменение параметров (для продвинутых)

Все настройки вынесены в начало `main.py`, в блок «Конфигурация». Их можно менять без правки логики.

| Параметр | Значение по умолчанию | Что делает |
|---|---|---|
| `PING_TIMEOUT_MS` | `500` | Таймаут одного ping в мс |
| `PING_WORKERS` | `60` | Потоков для ping-скана |
| `TCP_WORKERS` | `30` | Потоков для TCP-скана |
| `TCP_TIMEOUT` | `0.4` | Таймаут TCP-подключения (сек) |
| `TCP_PORTS` | `(80, 443, 445, ...)` | Список проверяемых портов |
| `INNER` | `58` | Ширина таблицы (внутри рамки) |

**Пример:** сделать таблицу шире — заменить `INNER = 58` на `INNER = 80`. Колонки подстроятся автоматически (реализовано через `_distribute`).

**Пример:** ускорить сканирование — увеличить `PING_WORKERS` до `100`, уменьшить `PING_TIMEOUT_MS` до `300`.

⚠️ **Не увеличивайте** `PING_WORKERS` выше `150` — Windows начнёт «задыхаться» от количества одновременных процессов `ping.exe`.

## 7. Возможные проблемы

### 7.1. «Не удалось найти активное сетевое подключение»

**Причина:** программа не нашла ни одного физического адаптера с IPv4 и шлюзом.

**Что делать:**
1. Проверьте, что Wi-Fi или Ethernet **включён** и подключён к сети.
2. Откройте `cmd` и выполните `ipconfig`. Найдите свой адаптер — у него должны быть **IPv4** и **Основной шлюз**.
3. Если IP начинается с `169.254.` — DHCP не выдал адрес. Переподключитесь к сети или задайте IP вручную.
4. Если у вас включён **только Radmin VPN** (без Wi-Fi) — программа специально **не** будет его сканировать. Включите реальную сеть.

### 7.2. «Устройства не найдены» (пустая таблица)

**Причина:** в подсети реально нет устройств, либо они все за client isolation.

**Что делать:**
1. Проверьте, что вы в правильной сети: `ipconfig` должен показать IPv4 в ожидаемой подсети.
2. Попробуйте пингануть роутер вручную: `ping 192.168.70.1`. Если ответа нет — возможно, сеть изолирует клиентов (типично для школ, офисов, кафе).
3. Запустите программу ещё раз — иногда ARP-таблица наполняется не сразу.

### 7.3. Кракозябры вместо рамок (`╔═╗` → `?` или `╬`)

**Причина:** консоль не поддерживает UTF-8.

**Что делать:**
1. Убедитесь, что в начале `main.py` вызывается `setup_console()`.
2. В PyCharm: **File → Settings → Editor → File Encodings** — поставьте **Global Encoding = UTF-8** и **Project Encoding = UTF-8**.
3. В cmd перед запуском выполните `chcp 65001`.

### 7.4. В шапке «Radmin VPN» или «VMware», а не Wi-Fi

**Причина:** фильтр виртуальных адаптеров не сработал (крайне редко, если название адаптера нестандартное).

**Что делать:**
1. Откройте `main.py`, найдите `VIRTUAL_ADAPTER_KEYWORDS`.
2. Добавьте туда ключевое слово из имени вашего адаптера (например, `'radmin'`, `'vmware'`).
3. Сохраните и запустите снова.

### 7.5. `AssertionError: row length ... != ...` при изменении ширины

**Причина:** это старая проблема, **исправлена в v0.4**. Если вы видите эту ошибку — у вас старая версия кода.

**Что делать:** обновите `main.py` до актуальной версии. В новой версии `COLS` вычисляется автоматически из `INNER`, поэтому рассинхронизация невозможна.

### 7.6. Долгое сканирование (больше 30 секунд)

**Причина:** медленный DNS при reverse-резолве, либо слишком много «живых» IP в сети с большим таймаутом ping.

**Что делать:**
1. Уменьшите `PING_TIMEOUT_MS` до `300`.
2. Убедитесь, что `DNS_TIMEOUT` не больше `1.0` (по умолчанию так).
3. Увеличьте `PING_WORKERS` до `80` (но не выше `150`).

## 8. Известные ограничения

- **Только Windows.** Программа использует системные утилиты `ipconfig`, `route`, `ping`, `arp`, доступные только в Windows.
- **Только IPv4.** IPv6-адреса не сканируются и не отображаются.
- **Только подсеть `/24`** (254 адреса). Для сетей крупнее (`/16`, `/22`) потребуется доработка.
- **Профиль сети Windows.** При профиле «Общедоступная» (Public) брандмауэр Windows 11 Home блокирует входящий ICMP. Устройства в такой сети будут отображаться как `ARP` или `TCP:<порт>`, а не `ONLINE`, даже если физически доступны. Для более полного сканирования переключите профиль на «Частная» (Private) или разрешите ICMP в брандмауэре.
- **Сканируется только одна подсеть.** Если машина подключена одновременно к Wi-Fi и Ethernet с разными подсетями, программа выберет **один** адаптер по метрике маршрута.
- **Права администратора не требуются**, но **исходящий ICMP и TCP должны быть разрешены** брандмауэром.
