# Найденные проблемы и исправления

## Bug #001 — Radmin VPN выбирается как основной адаптер
- **Обнаружено:** при запуске с включённым Radmin VPN программа сканировала
  26.31.225.0/24 вместо реальной сети 192.168.70.0/24.
- **Причина:** `get_local_ip()` возвращал первый IPv4 из `ipconfig`,
  а Radmin идёт в выводе раньше Wi-Fi.
- **Исправление:** добавлены фильтры по имени адаптера (`VIRTUAL_ADAPTER_KEYWORDS`)
  и по IP-диапазону (`VIRTUAL_IP_PREFIXES`); выбор по метрике маршрута.
- **Тест-кейс:** TC-LSM-01_003. Launch with Radmin.
- **Статус:**  Исправлено в v0.2.

## Bug #002 — Ping не отвечает при флаге `-a`
- **Обнаружено:** в первом прогоне на Wi-Fi-сети «0 пинг», хотя устройства
  реально отвечают.
- **Причина:** флаг `-a` в ping запускал reverse-DNS, который зависал на
  медленном DNS и не давал вывести `TTL=` до срабатывания таймаута subprocess.
- **Исправление:** убран `-a`; reverse-DNS вынесен в `reverse_dns()` с
  жёстким таймаутом через `threading.Thread.join(timeout)`.
- **Тест-кейс:** TC-LSM-02_001. Ping scan.
- **Статус:**  Исправлено в v0.2.

## Bug #003 — AssertionError при изменении ширины таблицы
- **Обнаружено:** при замене `INNER = 58` на `INNER = 80` программа падала
  с `AssertionError: row length 58 != 80`.
- **Причина:** `INNER` и `COLS` — две независимые константы. Меняли одну,
  забывали другую.
- **Исправление:** `COLS` теперь вычисляется из `INNER` через `_distribute()`.
  Добавлено взвешенное распределение, чтобы маленькие колонки не раздувались
  («эффект широкого Путина» при INNER = 218).
- **Тест-кейс:** TC-LSM-05_001. Table width.
- **Статус:**  Исправлено в v0.3.
